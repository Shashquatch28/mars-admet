# ml/ — data, featurization, models, evaluation, serving registry

Owns blueprint Modules 1, 3, 4, 5, 6 (post-MVP) and 11. Run as scripts from this
directory in `ml/.venv`; it is not an installed package (`pyproject.toml` only
gives pytest and ruff a rootdir).

## Layout

| Dir | Contents |
|---|---|
| `data/` | TDC acquisition (`acquire.py`, isolated env), standardization-driven `prepare.py`, tiered `dedup`, scaffold `split`, DILIst augmentation, EDA, dataset registry, lockfiles in `metadata/`, licences in `LICENSES.md` |
| `featurize/` | RDKit standardization, Morgan fingerprints, 217 descriptors, graph, ETKDG/MMFF conformers, scaffold, batched `pipeline`, on-disk `cache`, `build_cache.py` |
| `models/` | `base.py` interface, `xgboost_model.py` |
| `train/` | `run_xgboost_baseline.py` (one endpoint x one seed), `train_xgboost.py`, and the production sweep drivers `preflight_sweep.py`, `run_production_sweep.py`, `verify_sweep.py` |
| `eval/` | metrics, 5-seed aggregation (`evaluate.py`), Platt/temperature `calibration`, k-NN `applicability_domain`, `leakage_audit`, TDC comparability |
| `serve/` | inference registry (`registry.py`), predictor, rule-based SA score. This is what the API container imports. |
| `tracking/` | experiment run records, provenance capture, W&B logger |
| `configs/` | `experiment_config.py` |
| `utils/` | seeding |
| `tests/` | pytest suite (400 pass, 15 skip, about 9 min, 2026-10-14) |

Not tracked in git: `data/raw/`, `data/processed/`, `data/cache/`, `runs/`,
`artifacts/`, and `.venv/`. They are regenerated by the steps below.

## Environments

PyTDC pins `numpy<2` and `rdkit<2024.3.1` and has no Windows wheel for one of
its dependencies, so acquisition runs in an isolated environment
(`data/acquisition/README.md`). Everything else uses `ml/.venv`:

| File | For |
|---|---|
| `requirements-m1.txt` / `.lock.txt` | data + featurization, CPU only |
| `requirements-m2.txt` / `.lock.txt` | xgboost + wandb (the lock is not complete: matplotlib is unlocked) |
| `requirements-serving.txt` | the inference subset the API image installs |
| `requirements.txt` | loose superset, reference only; not a lockfile |

KERMT / torch / transformers are GPU-box only and are not in `ml/.venv`; the
KERMT training track and its code live on `milestone/m2-kermt`.

## Pipeline

```bash
cd ml
# 0. contracts importable
python -c "from mars_contracts import Endpoint; print(len(list(Endpoint)))"   # 15

# 1. acquire (isolated env, writes data/metadata/datasets.lock.json)
# 2. prepare: standardize -> dedup -> scaffold split -> calibration split -> leakage audit
#    outputs data/processed/<prep_id>/<dataset>/{train_val,test,calibration}.csv
# 3. warm the feature cache
python featurize/build_cache.py --prep-id <prep_id>
# 4. train one endpoint x one seed, or the whole 14 x 5 sweep
python train/run_xgboost_baseline.py --endpoint ames_mutagenicity --seed 0 --prep-id <prep_id>
PYTHONPATH=. python train/run_production_sweep.py --prep-id <prep_id>
# 5. verify what the sweep promoted into artifacts/
PYTHONPATH=. python train/verify_sweep.py
```

The sweep promotes each seed into `artifacts/<endpoint>/` (model, AD index,
calibrator) in the layout `serve/registry.py` documents; the API reads that
directory.

## Rules that hold across this directory

- The test set is never used for model selection, tuning or calibration.
- Seeds are fixed (`FIXED_SEEDS = 0..4`); every run records its config, data
  hash, environment and git SHA (`tracking/provenance.py`).
- No ad-hoc scripts in the repo root; throwaway scripts are git-ignored.
- Classification outputs are not validated probabilities. The UI labels them
  `score` (frontend ADR-023); do not describe them as calibrated probabilities
  in new docs.
